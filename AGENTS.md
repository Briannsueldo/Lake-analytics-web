Project Instructions
1. Technology Stack
React with TypeScript.
Tailwind CSS for styling.
Vite as the build tool.
Use functional components and React hooks.
Use Lucide React for icons when needed.
2. Design Philosophy

The quality of the visual design is a top priority.

Always follow these design skills when working on UI:

taste-skill
ui-ux-pro-max

These skills should guide visual decisions, composition, typography, color palettes, spacing, responsiveness, and user experience.

Never settle for generic templates or default AI-generated aesthetics.

Aim for premium, modern, distinctive, and professionally crafted interfaces.

3. Visual Standards
Prioritize strong visual hierarchy and intentional composition.
Use whitespace strategically, avoiding both overcrowded layouts and excessive empty spaces.
Maintain consistent spacing, typography, colors, and alignment.
Use subtle animations and micro-interactions where appropriate.
Avoid unnecessary cards, gradients, borders, and decorative elements.
Every visual element must have a clear design purpose.
Prioritize visual consistency across all components.
4. Development Standards
Write clean, readable, and maintainable TypeScript.
Use reusable and modular React components.
Keep components focused on a single responsibility.
Avoid unnecessary abstractions and overengineering.
Use semantic HTML and accessible UI patterns.
Avoid inline styles unless strictly necessary.
Do not introduce dependencies without a clear reason.
Keep the project structure organized.
5. Responsive Design
Follow a mobile-first approach.
Ensure layouts work properly on mobile, tablet, and desktop.
Avoid fixed dimensions when flexible layouts are more appropriate.
Pay particular attention to typography, spacing, and element positioning across breakpoints.
6. Assets
Inspect available assets before creating or replacing visual elements.
Respect provided images and design references.
Do not use low-quality, unrelated, or generic stock imagery.
Prefer CSS and SVG for simple decorative elements.
Never replace provided assets without a clear reason.
7. Workflow

Before implementing any major UI changes:

Inspect the existing project structure.
Understand the current design and implementation.
Review relevant design skills.
Analyze available assets and references.
Plan the visual changes before coding.

After implementation:

Review the result visually.
Check responsive behavior.
Fix layout inconsistencies and visual defects.
Verify that existing functionality remains intact.
8. Important Rules
Do not modify unrelated components or files.
Do not introduce additional sections or features unless explicitly requested.
Preserve existing functionality.
Do not make arbitrary design decisions when reference material is provided.
Prioritize design quality over implementation shortcuts.

Always think like a senior UI/UX designer and experienced frontend engineer.
